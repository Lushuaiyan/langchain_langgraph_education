# rag

rag的流程:
输入 -> 文档加载 -> 文本分块 -> 向量化 -> 向量储存 -> 检索 -> 输出 -> 生成

## 1. 文档的预处理
系统处理知识的第一步, 需要将文档分块
分块的三个核心参数:
- `chunk_size`: 每块的大小, 一般300-1000字符(中文约150-500字)
- `chunk_overlap`: 每块的重合程度, 确保语义的连贯性, 一般chunk_size的10%-20%
- `separators`: 按语义层次分割(段落>句子>字符)

> rag最重要的不是如何分块, 而是文档的质量要好, 结构清晰, 内容完整

## 2. 向量化
将文本映射为高维空间的数字向量, 语义相似的文本, 在向量空间中距离更近

中文embedding模型一般使用bge模型

## 3. 向量储存库
这里有两个选择:
1. faiss: 快速开发, 内存运行, 不是完整的向量数据库, 不支持增量更新和高并发的增删改查
2. chroma: 开源的向量数据库, 持久化存储

## 4. 构建完整的rag chain
定义检索器 -> 创建提示词模板 -> 连接组件

> 具体实践中有许多区别:
> 查询改写: 优化用户的输入(用户的问题很可能模糊, 不规范)
> 结果重排序: 先使用初步检索(top 20), 再更换更精准的模型选出(top 3-5)
> 混合检索: 兼顾语义和关键词匹配, 综合两种方式得分
